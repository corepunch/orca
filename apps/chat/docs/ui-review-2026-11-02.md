# Chat UI review — 2 November 2026

This review covers the other Chat screen families after the character-picker
fix. The reusable [Windows Phone cheatsheet](../../../docs/windows-phone-ui-cheatsheet.md)
separates Phone 7/8/8.1 guidance, Windows 10 guidance, ORCA behavior and
Chat decisions. [DESIGN.md](../DESIGN.md) remains the product baseline.

This is an audit and follow-up list. The findings below have not been
implemented by this documentation change. Earlier picker fixes remain in
the working tree.

## Coverage and evidence

| Screen family | Variants reviewed | Assessment |
| --- | --- | --- |
| Authentication | Phone, sign-in options, email code, email/password, signup, code entry | Branded form shell is deliberate; persistent labels are good here; sub-method navigation needs review |
| Startup and recovery | Session splash, reconnect retry, configuration failure, sign-out retry, global diagnostics/recovery | Branded loading and a recovery screen independent of the normal shell are intentional exceptions |
| Inbox | All, Unread, Pinned; populated, empty, loading, error and search | Appropriate related-data Pivot; active search is not disclosed in every affected pane |
| Contacts | Recent portrait wall, All directory; search, empty, loading, error and opening | Appropriate deliberate browsing Panorama; the wide section uses native parent-owned panning |
| New message | Direct/contact results, group selection/setup, channel creation, public-channel search/join, invitation entry/join | Whole-row commands work as a pattern; selection and field semantics need improvement |
| Settings | Profile header/photo commands, name/username, discovery, message previews, Number/Email linking and verification, sign out | Left-aligned hierarchy follows the established decision; inline linking can appear below the fold |
| Thread | Direct, group, channel/read-only, loading/empty, history and retry | Preserve chat grouping, bottom anchoring, photos and inline timestamps; improve feedback and auxiliary targets |
| Conversation details | Identity, rename, member roles/removal, invitation, leave confirmation, pin | Appropriate detail flow; row spacing accumulates |
| Photo viewer | Preview/full/cached, loading, failed download/retry and close | Correct immersive exception; preserve fitted image and usable Back |
| Character picker | Four columns, six-point gaps, header Back, save/failure | Recently fixed; keep the regression protections |
| Shared shell and styles | Root retention, app bar, toolbar, light/dark roles, corners, focus | Preserve deliberate adaptations; palette contrast and inset ownership need follow-up |

All families received source review. Selected geometry received native
offscreen measurements using the existing desktop binary at 390 logical
units. These measurements verify bounds, not painted screenshot appearance.
No fresh whole-app screenshot pass, device/keyboard interaction pass,
screen-reader verification, backend, live-account or Keychain checks were
performed for this audit. Older README previews are not evidence of the
current build's appearance.

## Findings, in follow-up order

### P2 — An active inbox search becomes invisible in two filtered views

[Inbox.xml](../Pages/Inbox.xml), lines 27–36, puts SearchBar only in All.
Unread and Pinned lack equivalent query/clear affordances. However,
[Data/Inbox.xml](../Data/Inbox.xml), lines 19–25, derives all three views
from the same `Matching(Search)` collection. Search in All, then swipe:
Unread/Pinned retain that filter with no visible explanation. This is a
source-confirmed interaction problem.

Share the search toolbar across affected views, or display the active query
and a Clear command in each affected pane. Preserve the query when returning
if that remains the chosen policy; do not leave it invisible. A regression
should search All, switch to each pane, verify disclosure/clear, and retain
the correct records after clearing.

### P2 — Group membership selection relies on colour

[conversations.lua](../views/conversations.lua), lines 80–87 and 105–109,
toggles `chat-soft` on a Button to mark recipients. There is no per-row
checkmark or native checked state. The selected-name summary helps, but it
does not make each row's selection unambiguous.

Use native CheckBox rows or a collection selection presentation with a
visible check and a clear selected count. Keep the whole row actionable.
Verify selecting/deselecting the same person, several people, keyboard
activation and both themes. This follows the cheatsheet's value-selection
model, rather than treating every selectable item as a command.

### P2 — Composer auxiliary hit targets are 36×36

[Composer.xml](../Pages/Composer.xml), lines 8 and 15, defines CancelEdit and
RemovePhoto at 36×36. Native layout confirms those actual sizes; main Attach
and Send are 48×48. The input's 44-point padding box plus its outside
two-point border on each edge correctly fills its 48-point slot.

Increase the auxiliary hit areas to the app's 44/48-point convention while
retaining the small glyphs. Keep edit cancellation and photo removal:
these are meaningful actions, unlike the redundant picker Cancel. This is
a comparison with the current app target convention, not a claim that 36
ORCA points automatically violates a historical pixel metric.

### P2 — Conversation failures use unusually small, centered text

[Composer.xml](../Pages/Composer.xml), line 4, gives ThreadStatus 11-point
centered text and 24-point horizontal margins. Other status blocks use
14-point text, for example
[Details.xml](../Pages/Details.xml), line 14, and
[Contacts.xml](../Pages/Contacts.xml), line 38.

Use the ordinary readable feedback presentation and consider leading
alignment for multi-line errors. Check a long service error at 320 width,
with a photo draft or edit banner present, and verify that recovery leaves
the composer usable. ORCA defaults `WordWrap` to true, with
`TextWrapping=WrapWithOverflow`; omitting an explicit wrapping attribute is
not evidence of a single-line bug. Long unbreakable strings still deserve
verification. The audit established the type/alignment inconsistency, not
a particular painted clipping defect.

### P2 — Ordinary text contrast needs attention in both themes

The following are deterministic sRGB relative-luminance calculations from
[app.css](../Styles/app.css), rather than screenshot or frosted-background
samples. Compare with Microsoft's [ordinary-text contrast guidance](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessible-text-requirements).

| Foreground / background | Ratio | Uses to review |
| --- | --- | --- |
| `#7a7a7a` / white | 4.29:1 | Light dim text and room previews, lines 10–11 |
| White / `#0078e7` | 4.34:1 | Light primary labels and sent text, lines 22–25 |
| `#d4e9ff` / `#0078e7` | 3.49:1 | Light sent metadata, line 26 |
| White / `#0084ff` | 3.66:1 | Dark primary labels and sent text, lines 47–50 |
| `#cfe6ff` / `#0084ff` | 2.86:1 | Dark sent metadata, line 51 |

These ordinary-text pairs fall short of a 4.5:1 target. Preserve the approved
blue identity while finding a contrast-checked foreground/background
combination; check hover/pressed states and avatars separately. Do not
claim a complete accessibility audit from this table. Translucent photo
timestamps and frosted bars also require testing their composited pixels.

### P2 — Number/Email editing can open out of view

[identity.lua](../views/identity.lua), lines 191–196, reveals LinkForm when
a Number or Email row is activated. The form is appended after the login
details at lines 269–270 without focusing/revealing its first input. On a
long Settings page, a tap may have little visible effect because the new
form lies below the viewport. This is a source-level behavior risk.

Prefer a focused child edit page with header Back, or focus/reveal the
inline form and preserve the draft. Verify the entry point with a scrolled
Settings page and an on-screen keyboard; avoid changing the account/linking
service as part of this presentation fix.

### P3 — Channel visibility is a cycling button

[conversations.lua](../views/conversations.lua), lines 166–170, uses a
Button whose text cycles Private/Public. A two-option RadioGroup, or a
dedicated picker if the design grows, shows both options and their current
value. This is a control-choice recommendation, not a demonstrated save bug.
The stored value and initial default must remain unchanged when changing
the presentation.

### P3 — Several persistent fields lose their labels after typing

Settings fields in [identity.lua](../views/identity.lua), lines 175–178,
and creation fields in [conversations.lua](../views/conversations.lua),
lines 44–45, rely primarily on placeholders and footnotes. Authentication
already uses a label-above-field pattern at identity.lua lines 59–60.

Use persistent labels where the entered value would otherwise obscure
which field is being edited. This is an app consistency recommendation;
Microsoft's text-box guidance permits a label or placeholder when the
purpose needs explanation, rather than banning all placeholders.

### P3 — Details spacing adds up across nesting levels

[Details.xml](../Pages/Details.xml), line 23, spaces member rows by 14;
[MemberRow.xml](../Templates/MemberRow.xml), line 3, pads each row by six
vertically. Two ordinary nonadmin rows have a **26-point measured gap
between their 52-point avatar tiles**: 6 + 14 + 6. Role/remove commands
make admin rows taller still.

Choose a visible people-row gap and give it one owner. Keep section spacing
separate from row padding, so repeated content does not inherit a section
gap at every boundary. Compare Contacts, New message and member lists at
the artwork edges, without forcing unrelated screen structures to have
identical row heights.

### P3 — Full-bleed toolbar compensation assumes a stale inset

[Inbox.xml](../Pages/Inbox.xml), line 27, and
[components.lua](../views/components.lua), lines 229–233, compensate with
minus-20 side margins and plus-20 padding. Native 390-point measurement:

| Node | Global horizontal bounds |
| --- | --- |
| PivotItem | x=12, width=366 |
| SearchBar | x=−8, width=406 |
| Search input padding box | x=14, width=318 |
| Search input outside border | Starts at x=12 |
| ClearSearch | x=334, width=44 |

The foreground **does align**. The backdrop overdraws eight points beyond
each screen edge, so this is a maintainability concern, not a confirmed
visible alignment defect. Derive background extension from the actual
owning inset, while preserving field alignment and docked-bar behavior.

### P3 — Authentication needs a documented navigation exception

[identity.lua](../views/identity.lua), lines 148–160, uses a 36-point logo,
38-point title and `Padding="24 28"`, rather than Pivot page chrome.
This is the established branded/Teams-inspired form direction and should
remain an explicit exception. The sub-method routes lack a header Back;
review how users return to options from code/password/signup steps.

[C.command](../views/components.lua), lines 103–110, reserves a 52-point
icon column plus a 14-point gap and uses 20-point single-line ellipsis
text. At 320 width the auth page has only 272 points inside its outer
insets. Long localized method names may truncate; validate the rendered
labels rather than guessing a width from character count.

### P3 — Empty-state copy does not identify the current view

[Inbox.xml](../Pages/Inbox.xml), lines 48 and 69, repeats general caught-up
and start-chat copy in Unread and Pinned. Prefer specific empty states such
as “no unread conversations” or “no pinned conversations”, with an action
appropriate to that view. Keep temporarily empty Pivot views present.

### P3 — Recovery report uses a selection control for static content

[diagnostics.lua](../diagnostics.lua), lines 65–71, gives its read-only
report to `ListBox`, although it has one static TextBlock and no user choice
to make. Prefer a plain scrolling container for the report unless selecting
a report item serves an explicit purpose. Preserve the independent recovery
screen and its Return to chat action; they must remain usable when the
normal shell fails. This is a semantic control-choice recommendation, not
a proven recovery failure.

## Preserve these deliberate choices

- Inbox's Pivot filters related records. Contacts' Panorama is a different
  browsing structure, not an accidental inconsistency.
- A locked single-item Pivot is Chat's shared title shell for task/detail
  pages. It is an ORCA adaptation; do not cite historical swipe-Pivot rules
  as an endorsement of editable multi-page Pivots.
- The root ApplicationBar switches retained Chats, Contacts, New and
  Settings pages; its current destination is disabled. This is a product
  choice rather than the conventional command/navigation distinction.
- Settings uses native CheckBox controls by explicit user decision. Preserve
  them while making save behavior clear.
- Keep the six-point corner treatment, semantic palette roles, keyboard-only
  focus rings, frosted chrome and the 58-point composer/bar correspondence.
- The viewer remains black with a fitted image and preview/retry behavior.
  It does not need ordinary form gutters or a Panorama title.
- Startup's gradient, centered 128-point logo and loading indicator are
  intentional branding. The reconnect/configuration/sign-out retry pages
  use the ordinary task shell ([App.lua](../App.lua), lines 340–388).
  Check the splash's fixed indicator offset on short landscape viewports
  before claiming adaptive visual coverage.
- Keep Cancel in the leave-confirmation decision. The character picker has
  header Back only, four columns and equal six-point gaps.

## Validation for follow-up changes

Use the current XML desktop binary and the smallest affected offline test.
Rebuild only when native code/API changes or the binary is missing. These
are follow-up commands, not a claim that every suite was rerun for this
documentation-only review:

```sh
build/bin/orca -test=tests/test_chat_app.lua          # forms, creation, settings/details
build/bin/orca -test=tests/test_chat_contacts.lua     # Contacts Panorama/search/retention
build/bin/orca -test=tests/test_chat_timeline.lua     # timeline/composer/history
build/bin/orca -test=tests/test_chat_photo_viewer.lua # immersive viewer
build/bin/orca -test=tests/test_chat_avatars.lua      # picker, screen taps, Settings photo
build/bin/orca -test=tests/test_layout.lua            # engine content measurement
build/bin/orca -test=tests/test_metro.lua             # shared Pivot/Panorama/app-bar behavior
```

Test at 320/390 widths and a wider/landscape viewport, both themes, long
names/translations, safe areas and keyboard. Assert global artwork spacing
and full touch bounds. Use real pointer routing for touch regressions;
direct event sends alone missed the original zero-height image-button bug.
Native/device visual verification remains a follow-up requirement before
claiming a complete visual pass of every screen.
